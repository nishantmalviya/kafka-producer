⚡ QUICK START (5 MINUTES)
================================================================================

Step 1: Start Kafka
  $ docker-compose up -d
  $ sleep 30

Step 2: Build Application
  $ mvn clean install
  
Step 3: Run Application
  $ java -jar target/kafka-producer-1.0.0.jar
  
Step 4: Test API
  $ curl http://localhost:8080/api/v1/kafka/health
  
Step 5: Publish Message
  $ curl -X POST http://localhost:8080/api/v1/kafka/publish \
      -H "Content-Type: application/json" \
      -d '{"message":"Hello Kafka!","key":"test-key"}'

Expected Response:
  {
    "status": "SUCCESS",
    "timeTakenMs": 45,  ← Performance metric!
    "offset": 0,
    "partition": 0,
    "topic": "my-topic"
  }

🔐 CONFIGURATION FOR YOUR ENVIRONMENT
================================================================================

LOCAL DEVELOPMENT (No Auth):
┌─────────────────────────────────────────────────────────────────┐
│ spring.kafka.bootstrap-servers=localhost:9092                   │
│ kafka.topic.name=my-topic                                       │
└─────────────────────────────────────────────────────────────────┘

JAAS Authentication (SASL/PLAIN):
┌─────────────────────────────────────────────────────────────────┐
│ spring.kafka.properties.security.protocol=SASL_SSL              │
│ spring.kafka.properties.sasl.mechanism=PLAIN                    │
│ spring.kafka.properties.sasl.jaas.config=\                      │
│   org.apache.kafka.common.security.plain.\                      │
│   PlainLoginModule required username="user" \                   │
│   password="pass";                                              │
└─────────────────────────────────────────────────────────────────┘

SSL/TLS Configuration:
┌─────────────────────────────────────────────────────────────────┐
│ spring.kafka.properties.ssl.truststore.location=\               │
│   file:/path/to/truststore.jks                                  │

📊 PERFORMANCE METRICS
================================================================================

The 'timeTakenMs' field shows time from message send to Kafka acknowledgement.

Lower values = better performance:
  ✓ 10-20ms  = Fast (acks=1, local)
  ✓ 40-60ms  = Good (acks=all, single broker)
  ✓ 80-150ms = Normal (acks=all, 3 replicas)
  ✗ >200ms   = Investigate (network/broker issues)

Use this metric to:
  • Monitor end-to-end latency
  • Analyze configuration impact
  • Identify bottlenecks
  • Understand replication overhead
